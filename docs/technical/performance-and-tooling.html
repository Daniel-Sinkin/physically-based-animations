Performance and Tooling

Performance-oriented data layout, memory discipline, and reproducible diagnostics.

SoA Memory Access Patterns

The physics step iterates contiguous arrays (SoA) instead of arrays of structs. This improves cache locality when a stage only touches a subset of fields. 

// Example access pattern in integration stages
for each i in [0, N):
  v[i] += (force[i] * inv_mass[i]) * dt
  x[i] += v[i] * dt

Backing container: RigidBodySOA in src/pba/physics/physics_types.hpp.

Transient Allocation Strategy

Contact data is allocated in a per-step arena and reset once each step, avoiding fragmented per-contact dynamic allocations.

  • src/pba/core/arena_allocator.hpp
  • src/pba/physics/physics_context.hpp: contact_arena
  • src/pba/physics/physics_context.cpp: contact_arena.clear()

Parallel Policy Wrapper

parallel_for_index provides a single loop policy abstraction. The same call sites run with OpenMP parallelism when enabled, or serial fallback otherwise.

  • src/pba/core/parallel_for.hpp
  • Used in solver integration, damping, and collision preprocessing

Runtime Diagnostics

The UI and headless modes expose complementary diagnostics:

  • Physics Debug panel: broadphase candidates, narrowphase tests, contacts, and kinetic energy history
  • Headless runs: average and max step time summaries plus scene/step parameterization

Relevant files:

  • src/pba/ui/ui.cpp
  • src/app/headless_main.cpp

Fixed-Step Scheduling

Physics runs at fixed time_step with an accumulator loop in EngineContext::run(). This separates simulation cadence from render cadence.
