Physics Pipeline

Exact per-step ordering, transient memory strategy, and solver stages.

Data Layout

Body state is stored in a structure-of-arrays container (RigidBodySOA):

  • positions[], velocities[], inv_masses[]
  • orientations[], angular_velocities[], inv_inertia_worlds[]
  • bit-like state flags: asleep_flags[], grabbed_flags[]

Defined in src/pba/physics/physics_types.hpp.

Per-Step Execution Order

PhysicsContext::step() drives the pipeline in this order:

  • Clear per-step contact arena
  • Update world-space inverse inertia tensors
  • Apply simple and complex forces
  • Integrate forces, then integrate velocities/orientation
  • Generate OBB contacts (broadphase + narrowphase)
  • Warm-start from contact cache
  • Velocity solve, then positional solve
  • Write back cache, apply damping/sleep, clear accumulators

Main implementation: src/pba/physics/physics_context.cpp.

Contact Memory Access Pattern

Contact generation writes Contact records into a single ArenaAllocator region (contact_arena). The solve passes iterate over this contiguous span repeatedly: 

for (auto& contact : contact_arena.as_span<Contact>()) {
    // warm start / velocity iterations / position iterations
}

This keeps per-step allocations bounded and avoids per-contact heap churn.

Parallel Regions

Loops over body arrays use parallel_for_index, which maps to OpenMP when enabled, otherwise serial iteration with the same callsite contract.

  • src/pba/core/parallel_for.hpp
  • Used in solver integration/damping and collision precompute stages
