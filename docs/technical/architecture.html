Architecture Overview

Top-level module boundaries, ownership model, and update control flow.

Top-Level Composition

The runtime is coordinated by EngineContext, which owns both simulation and rendering/editor systems:

  • SimulationContext: world state + physics state
  • GfxContext: OpenGL resources, viewport, and ImGui tools
  • Input and fixed-step loop orchestration

Primary source files:

  • src/pba/engine/engine_context.hpp
  • src/pba/engine/engine_context.cpp

World and Entity Ownership

World keeps entity metadata and a transform SoA, with an id → index map for direct lookup. Entity removal uses swap-erase to keep storage dense.

  • src/pba/scene/world.cpp
  • src/pba/scene/world_types.hpp (TransformSOA)

Transform data is split into contiguous arrays (pos_x, pos_y, pos_z, scale_x, ...), backed by a local arena allocation.

Clocking and Deterministic Step Schedule

Simulation advances in fixed increments (time_step) via an accumulator loop: 

accumulator += frame_dt;
while (accumulator >= fixed_dt) {
    simulation.physics.step();
    accumulator -= fixed_dt;
}
simulation.sync_physics_to_world();

This keeps physics update cadence stable even when render frame times vary.
