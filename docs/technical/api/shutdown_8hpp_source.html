9// For development and showcases I use the watcher.sh script which uses
10// watchexec to (gently) restart the program whenever some file gets saved.
11//
12// That is done by sending a SIGTERM signal which is an ignorable terminal
13// signal. Indirectly when the watcher gets closed (for example by <CTRL+C>)
14// then it sends a SIGINT signal which also gets processed by the program.
15//
16// Earlier iterations used SIGKILL and didn't need to explicitly handle
17// the signal but that is unstable when handling IO requests.
18//
19// As per the C++ standard calling arbitrary functions (e.g. GLFW, OpenGL library
20// functions) is UB, see https://en.cppreference.com/w/cpp/utility/program/signal
21//
22// So I use a standard workaround by setting a signal-safe atomic flag
23// (g_request_close_sig) and read that, storing its value into g_request_close
24// which then invokes the actual shutdown. (Probably overkill for our safety reqs.)
25inline std::atomic_bool g_request_close{false};
26inline volatile std::sig_atomic_t g_request_close_sig{0};
27} // namespace ds_pba
