Practical DoD Lessons Applied

This codebase already follows several patterns discussed in Vittorio Romeo's CppCon 2025 keynote on practical data-oriented design.

  • Data-first hot loops: physics state is stored as SOA columns for stream-friendly iteration in solver and collision passes.
  • Group by usage, not by type hierarchy: broadphase scratch data is split into scalar columns (aabb_min_x, aabb_max_x, etc.) to keep pruning passes tight.
  • Reduce allocation churn in frame-critical paths: contacts are written into a transient arena and reused every step.
  • Keep abstraction at coarse boundaries: world/editor APIs remain object-friendly, while throughput-critical internals stay data-oriented.
  • Standardize parallel traversal entry points: parallel_for_index keeps index kernels portable across serial and OpenMP builds.

Related references: C++ Performance Talks.

AOS vs SOA

The codebase uses both layouts with explicit roles. Entity metadata is kept in AOS form (std::vector<Entity>), while frequently updated transform and physics state are organized in SOA form for tighter field-wise scans.

This split keeps ownership and editor-facing data simple, while letting physics and transform-heavy code iterate through contiguous columns such as position, velocity, and inverse mass. 

// src/pba/scene/world.hpp
std::vector entities_{};
TransformSOA transforms_{k_max_number_objects};

// src/pba/physics/physics_types.hpp
std::vector positions{};
std::vector velocities{};
std::vector inv_masses{};
std::vector orientations{};
std::vector inv_inertia_worlds{};

Relevant files: src/pba/scene/world_types.hpp, src/pba/physics/physics_types.hpp, src/pba/scene/world.cpp.

Transient Arena Allocation

Per-step collision contacts are written into a linear arena (ArenaAllocator) and reset at the beginning of each physics step. This avoids frequent heap allocations in the hot simulation loop and keeps contact data in one contiguous region for solver passes. 

// src/pba/physics/physics_context.hpp
ArenaAllocator contact_arena{k_physics_step_arena_bytes};

// src/pba/physics/physics_context.cpp
contact_arena.clear();
debug_collision_stats = generate_obb_contacts(bodies_soa, contact_arena, collision_scratch, true);
for (auto& contact : contact_arena.as_span<Contact>()) {
    // warm start + solve passes
}

Arena capacity is configured with k_physics_step_arena_bytes = 256 MiB in src/pba/core/constants.hpp.

Broadphase and Cache Behavior

Broadphase uses separate scalar arrays for AABB bounds in CollisionScratch, then performs sweep-and-prune over sorted min-x values. Candidate rejection on y/z overlap is done before narrowphase SAT work.

The layout is intentionally columnar (aabb_min_x, aabb_max_x, etc.) to make the pruning phase a compact streaming pass with low branch and memory overhead per candidate. 

// src/pba/physics/collision.hpp
std::vector aabb_min_x{}, aabb_min_y{}, aabb_min_z{};
std::vector aabb_max_x{}, aabb_max_y{}, aabb_max_z{};
std::vector sort_order{};
std::vector active{};
std::vector candidate_pairs{};

// src/pba/physics/collision.cpp
std::sort(sort_order.begin(), sort_order.end(), by_min_x);
for (usize idx : sort_order) {
    prune_active_on_x(idx);
    test_yz_overlap_and_emit_candidates(idx);
}

Parallel Index Traversal

A thin parallel_for_index wrapper is used for index-based loops in physics build/update stages. It keeps call sites uniform and falls back to a serial loop when OpenMP is not enabled. 

// src/pba/core/parallel_for.hpp
template <class Fn>
inline auto parallel_for_index(usize count, Fn&& fn) -> void {
#if defined(DS_PBA_USE_OPENMP)
  #pragma omp parallel for schedule(static)
  for (i64 i = 0; i < static_cast<i64>(count); ++i) fn(static_cast<usize>(i));
#else
  for (auto i = 0zu; i < count; ++i) fn(i);
#endif
}

Used in src/pba/physics/collision.cpp, src/pba/physics/solver.cpp, and src/pba/physics/physics_context.cpp.
